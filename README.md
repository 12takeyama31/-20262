# 部旅行

33名の団体旅行を対象にした、ブラウザ内で動作する部屋割り予約Webアプリです。公開表示にはサンプルの予定と架空の参加者名を使用しています。

部屋は「スーペリア A」「デラックス A」（各6名）、「スーペリア B」「モダンルーム A・B」「ファミリー A」（各5名）の6室、合計定員32名です。各部屋カードでは部屋タイプごとの写真2枚をスライド表示できます。

削除済みのデラックスB・ファミリーBや旧構成の部屋予約が保存されている場合は、残っている部屋へ可能な限り自動移行します。

参加者向けの「ログイン」と「新規登録」は別画面に分かれており、上部の切り替えから移動できます。

「バス座席予約」では、ログインしていない方も往復の予約状況と予約者名を閲覧できます。部屋予約と同じ参加者アカウントでログインすると、45席の座席表から行き・帰りを1席ずつ予約できます。電話番号やメールアドレスの追加登録は不要です。予約した座席はSupabaseの `bus_seat_reservations` に保存され、ほかの参加者には予約済みとして表示されます。

「予定表」では、全員が旅行の工程表を確認できます。管理者ページから日付・時刻・予定・場所・メモを追加し、編集・削除できます。

## 起動方法

`index.html` をブラウザで開いてください。ローカルサーバーを利用する場合は、このフォルダーで以下を実行できます。

```powershell
python -m http.server 4173
```

その後、`http://127.0.0.1:4173/` を開きます。

## 管理者の初期ログイン情報

- メールアドレス: `admin@group-trip.jp`
- パスワード: `Room33!`

これはブラウザだけで動くデモ用の初期値です。本番運用時はバックエンド認証へ置き換えてください。

管理者ページの「参加者アカウント管理」では、各参加者の数字4桁のパスワードを確認・変更できるほか、参加者アカウントを削除できます。削除した参加者の部屋予約とバス座席予約も同時に解除されます。この一覧は管理者ログイン中だけ表示されます。

## データ保存

予約系データはSupabase、ログイン状態や管理者設定などの簡易データはブラウザの `localStorage` に分離して保存します。

Supabase:

- `reservations`: 部屋予約
- `itinerary_items`: 予定表
- `bus_seat_reservations`: バス座席予約

localStorage:

- `groupTrip.participants.demo.v1`: サンプル名に切り替えた参加者
- `groupTrip.admin.v1`: 管理者
- `groupTrip.session.demo.v1`: ログイン状態
- `groupTrip.resetRequests.v1`: パスワード再設定申請

既存の部屋・バス予約は、予約ID・座席・4桁パスワードを維持して架空の名前に変更しています。以前の本名ではログインできません。新しいログイン名の対応表は公開フォルダーの外にある `private-reservation-name-map-20261018.csv` です。以前のブラウザ内の実名アカウントはデモ用の保存領域へ引き継ぎません。

## データベース化するとき

参加者アカウント、管理者設定、パスワード再設定申請もデータベースへ移行する場合は、`app.js` の `loadState`、`saveAll`、`saveSession`、`submitResetRequest` をAPI呼び出しに置き換えます。予約確定処理は、同時予約による定員超過を防ぐため、サーバー側のトランザクションで行ってください。管理者パスワードは平文保存せず、サーバー側でハッシュ化してください。

参加者データには、名前と数字4桁の `password` を保存します。部屋予約とバス座席予約はSupabase側の予約テーブルから反映します。既存参加者に `password` がない場合は、次回ログイン時に入力した数字4桁を初回パスワードとして設定します。ブラウザのみで動く現在の構成ではパスワードも `localStorage` に保存されるため、本番環境では参加者パスワードもサーバー側でハッシュ化してください。
